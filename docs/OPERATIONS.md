# Как поднять платформу к сессии экзаменов

Платформа запускается только на время сессии на компьютере учителя (Windows).
База данных — один файл SQLite `english_exam.db` в папке проекта. Ниже — чек-лист
по порядку. Команды выполняются в папке проекта (`cmd` или PowerShell).

> **`make` на Windows обычно не установлен.** У каждой команды `make …` ниже
> указан прямой эквивалент `python -m …` — используйте его. Перед командами
> активируйте виртуальное окружение: `.venv\Scripts\activate` (cmd) или
> `.venv\Scripts\Activate.ps1` (PowerShell).

## 1. За день до экзамена: обновить и подготовить

```
git pull
make install            # = pip install -r requirements.txt
```

### Настроить `.env`

Файл `.env` лежит в корне проекта (если его нет — скопируйте `.env.example` в `.env`).
Он не попадает в git, ключи в нём никому не отправляются.

| Параметр | Что поставить | Зачем |
|---|---|---|
| `TEACHER_PASSWORD` | свой пароль | вход в панель учителя. Пока стоит пароль по умолчанию, панель работает только на этом компьютере |
| `ADMIN_TOKEN_SECRET` | случайная строка (см. ниже) | подпись токенов входа. Без неё через туннель войти нельзя |
| `ENVIRONMENT` | `production` | на сессии со студентами через интернет. `dev` — только для разработки |
| `GEMINI_API_KEY` | ключ с https://aistudio.google.com/apikey | автоматическая проверка письма. Пусто — письмо уходит в ручную проверку |
| `ANALYSIS_LLM` | `writing` или `off` | `writing` — дополнительное «второе мнение» Gemini о письменных ответах (честность). Вердикт о списывании всё равно строят правила, оценку он не меняет |

Сгенерировать `ADMIN_TOKEN_SECRET`:

```
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Скопируйте результат в `.env`: `ADMIN_TOKEN_SECRET=...` (без кавычек).

### Обновить базу данных

```
make migrate            # = alembic upgrade head
```

(`make session` ниже делает это сам, но лучше проверить заранее.)

### Тесты и ученики

1. Запустите сервер (`make session`, см. п. 2) и откройте панель учителя:
   http://127.0.0.1:8000/web/teacher.html
2. Импортируйте тест: в панели (импорт JSON) или командой
   `make import-test file=test.json` (= `python -m app.content.transfer import --file test.json`).
   Тест попадает в черновики.
3. Проверьте его в очереди проверки и нажмите **«Одобрить и опубликовать»** —
   только после этого ученики могут его открыть.
4. Добавьте учеников в **«Список учеников»** теста.
5. Распечатайте карточки с PIN-кодами: в списке учеников теста нажмите
   **«Печать PIN-карточек»** (A4, 10 карточек на листе: имя, PIN из 4 символов и
   ссылка). Разрежьте и раздайте — каждый ученик выбирает своё имя и вводит свой PIN.
   Забыл или потерял PIN — нажмите **«Сгенерировать новый PIN»** у этого ученика
   (это же снимает блокировку после 5 неверных попыток).
   Для детских уровней (Pre A1 Starters, A1 Movers, A2 Flyers) ученик может
   переключить подсказки интерфейса на УКР / РУС на стартовом экране (сами задания
   остаются на английском).
6. (Необязательно) Задайте **окно экзамена** — см. ниже.

### Окно экзамена (когда тест можно начать)

В «Ученики и результаты» теста — блок **«Окно экзамена»**. Без окна опубликованный
тест открыт всегда (как раньше).

- **«Открыть в» / «Закрыть в»** — время по часам *этого* компьютера (сервер хранит
  UTC). До открытия ученик видит «Тест откроется: …» и начать не может; после
  закрытия новую работу начать нельзя («Тест закрыт»).
- **Закрытие — жёсткий конец сессии.** Срок каждой работы = начало + длительность
  теста, но не позже «закрыть в» + запас. Кто начал поздно — получит меньше времени.
  Ставьте закрытие не раньше «последний ученик начнёт» + длительность.
- **«Запас на опоздание, мин»** продлевает закрытие (и для старта, и для срока).
- **Уже начатые работы дописываются до своего срока**, даже если окно закрыли или
  перенесли: срок фиксируется при старте, его не двигает ни одно изменение окна (чтобы
  дать ученику время — «Переоткрыть» с добавкой минут в списке учеников).
- **Быстрые кнопки:** «Открыть сейчас на N минут» (по умолчанию длительность + 10) и
  «Закрыть сейчас» (новые старты запрещены сразу, начатые работы дописываются).
- Окно можно менять в любой момент, даже у опубликованного теста с работами — это не
  ключ ответов и не содержание.
- **Время сервера** показано в шапке панели. Если там предупреждение «часы этого
  компьютера расходятся с сервером» — поправьте часы: окна и таймеры идут по серверу.
- В банке тестов колонка «Окно экзамена» показывает состояние каждого теста; время
  окна печатается и на PIN-карточках.

### Длительность тестов YLE (Starters / Movers / Flyers)

Таймер серверный и **не останавливается**, а аудирование идёт в реальном времени,
поэтому длительность детских тестов считается по одному правилу:
**длительность = все аудиозаписи теста (в минутах, округление вверх) + официальное
время Reading & Writing (Starters 20, Movers 30, Flyers 40) + 10 минут запаса
(просьба школы), итог округляется вверх до кратного 5.** Пример: Flyers Vol 2 —
аудио 30:33 → 31 + 40 + 10 = 81 → **85 мин**. Сейчас: Starters Vol 1 / Vol 2 —
55 / 55, Movers Vol 1 / Vol 2 — 70 / 75, Flyers Vol 1 / Vol 2 — 80 / 85 (разница
между томами — только из-за длины записей). Это настройка теста (её можно поменять в
редакторе), сам таймер работает как раньше.

## 2. День экзамена: запуск сессии

```
make session                        # = python -m scripts.session
make session tunnel=cloudflared     # = python -m scripts.session --tunnel cloudflared
```

Что делает `session` (каждый шаг пишет строку в консоль):

1. проверяет `.env`: с туннелем пароль и `ADMIN_TOKEN_SECRET` обязаны быть заданы
   (иначе сессия не стартует); без `GEMINI_API_KEY` — предупреждение;
2. обновляет базу (`alembic upgrade head`);
3. делает резервную копию `backups\english_exam-…-presession.db`;
4. запускает сервер на порту 8000 ровно с **одним** процессом (`--workers 1`) —
   так и нужно, не меняйте;
5. каждые 15 минут делает резервную копию (`every=10` — каждые 10 минут);
6. по **Ctrl+C** останавливает сервер и делает финальную копию `…-final.db`.

Окно с `session` не закрывайте крестиком — только Ctrl+C, иначе не будет
финальной копии.

### Доступ для учеников

**Ученики в той же сети (класс, Wi-Fi):** ссылка `http://<IP компьютера>:8000/...`
(IP — команда `ipconfig`; Windows может спросить разрешение брандмауэра — разрешите
для частной сети).

**Ученики из дома — через туннель (HTTPS).** Запустите `make session tunnel=…`,
затем во **втором** окне — команду, которую `session` напечатает:

```
cloudflared tunnel --url http://localhost:8000
```

или

```
ngrok http 8000
```

Туннель выдаст адрес `https://….trycloudflare.com` (или `https://….ngrok-free.app`).
Он меняется при каждом запуске — отправляйте ссылку ученикам в день экзамена.
У бесплатного ngrok ученик сначала видит страницу-предупреждение — нужно нажать
«Visit Site».

> **Не делитесь скриншотами инспектора ngrok** (http://127.0.0.1:4040): он
> показывает все запросы учеников вместе с их секретными токенами попыток
> (`X-Attempt-Token`, `?token=`). С таким токеном можно отвечать за ученика.

Ссылка на тест (одна на тест, для всех учеников):

```
https://<адрес туннеля>/web/exam.html?test=<id теста>
```

Готовую ссылку можно скопировать в панели учителя у теста.

Про прокси: `session --tunnel` запускает сервер с
`--proxy-headers --forwarded-allow-ips=127.0.0.1` — сервер доверяет адресам
учеников только от агента туннеля на этом же компьютере (тогда защита от
подбора PIN видит настоящие адреса учеников; без этого все выглядят как один
адрес — это допустимо: опечатки класса всё равно никого не блокируют, см. п. 3). Если прокси стоит на **другом**
компьютере, укажите его IP: `python -m scripts.session --tunnel cloudflared --forwarded-allow-ips=<IP прокси>`.
Никогда не ставьте `*`.

## 3. Во время экзамена

### Неверные PIN и блокировки

- **5 неверных PIN подряд на одно имя** (за 5 минут) блокируют вход под этим
  именем на 5 минут — даже с правильным PIN. Таймер ученика при этом **идёт**.
- Опечатки класса за одним школьным адресом (Wi-Fi, общий IP, туннель) **не**
  блокируют класс: адрес притормаживается (на 30 с, потом дольше) только если
  с него неверные PIN приходят на **5 и больше разных учеников**, которые потом
  так и не вошли (это похоже на подбор, а не на опечатки).
- **Риск:** любой, у кого есть ссылка, может нарочно ввести 5 неверных PIN на
  имя одноклассника и заблокировать его на 5 минут. Если в списке учеников
  появилась жёлтая плашка **«Много неверных PIN для этого теста…»** или
  **«Заблокированы: …»** — посмотрите, на кого и сколько неверных PIN, и нажмите
  **«Снять блокировки»** (снимает все блокировки этого теста: у учеников и с
  общего адреса; PIN-коды не меняются). Ученик сразу входит со своей карточкой.
  Повторяется — выдайте пострадавшему **«Сгенерировать новый PIN»** и выясните,
  кто вводит чужие PIN (в консоли сервера строки `PIN LOCK` / `PIN THROTTLE` /
  `PIN ALERT`).
- Блокировки хранятся в памяти сервера: перезапуск `session` тоже их снимает.

- В панели учителя включите **«Наблюдать вживую»** — список и результаты
  обновляются каждые 5 секунд: кто начал, кто сдал, баллы, подозрительность.
- Вердикт о списывании — только **рекомендация**: он никогда не меняет оценку.
  Перед выводами смотрите хронологию действий ученика.
- Таймер идёт на сервере и **не останавливается**, если ученик свернул вкладку.
- **У ученика упал браузер / сел телефон:** пусть снова откроет ту же ссылку и
  войдёт под собой — тест продолжится с того же места, ответы сохранены,
  время продолжает идти. С другого устройства тоже можно (в панели это
  отметится как «продолжил тест на другом устройстве»).
- **Сервер упал / компьютер перезагрузился:** запустите `make session` снова.
  Ученики обновляют страницу и продолжают.

## 4. После экзамена

1. Дождитесь, пока у всех появится оценка (значок ⏳ — оценка ещё считается;
   письмо проверяет Gemini, это до минуты на работу).
2. Если у кого-то «⚠ нет оценки» — нажмите **«Дооценить все»**.
3. Письмо без ключа Gemini — оцените вручную в карточке ученика.
4. Выгрузите результаты: **CSV** (открывается в Excel), **«Печать отчёта»** —
   печатный отчёт по ученику.
5. Остановите сервер: **Ctrl+C** в окне `session` (будет финальная копия).
6. Дополнительная копия вручную (можно и при работающем сервере):

   ```
   make backup                 # = python -m scripts.backup_db
   make backup assets=1        # + копия картинок и аудио (var\assets)
   ```

### Где лежат копии

Папка `backups\` в проекте:

- `english_exam-ГГГГММДД-ЧЧММСС.db` — автоматические, хранятся последние 30
  (время в имени — **UTC**, для Киева это на 2 часа меньше зимой и на 3 летом;
  местное время копии написано в строке `backup start` в консоли)
  (`BACKUP_KEEP` в `.env`), старые удаляются сами;
- `…-presession.db`, `…-final.db`, `…-prerestore.db` — «вехи», не удаляются
  автоматически;
- `assets-ГГГГММДД-ЧЧММСС\` — копии картинок/аудио (`assets=1`).

Каждая копия проверяется (`integrity_check`) и в консоли видно, сколько в ней
попыток и ответов. Если копия не удалась (антивирус держит файл, нет места на
диске), в консоли будет строка `backup failed` — сервер продолжает работать,
следующая копия будет по расписанию. Папку копий можно сменить в `.env`: `BACKUP_DIR=D:\exam-backups`.

### Восстановить из копии

1. Остановите сервер (Ctrl+C). Пока сервер работает (занят порт 8000 или жив
   процесс `session` — файл `var\session.pid`), восстановление откажется.
   Если окно `session` уже закрыто, а восстановление всё равно пишет
   «exam session pid … is still running», удалите файл `var\session.pid` вручную
   (`del var\session.pid`) и повторите.
2. Выполните:

   ```
   make restore file=backups\english_exam-20261117-101500.db
   python -m scripts.restore_db --file backups\english_exam-20261117-101500.db
   ```

   Текущая база сначала сохраняется как `…-prerestore.db` — если ошиблись
   копией, восстановите её тем же способом.
3. Картинки/аудио восстанавливаются вручную: скопируйте содержимое
   `backups\assets-…\` в `var\assets\`.
4. Запустите `make session`.

## 5. Между сессиями

- Сохраните папку `backups\` (и `english_exam.db`) на флешку или в облако.
- Перед следующей сессией обновите код и зависимости и прогоните тесты:

  ```
  git pull
  make install
  make migrate
  make test               # = python -m pytest -q
  ```

  Все тесты должны пройти. Если нет — не запускайте сессию, сообщите разработчику.
- Ключ Gemini и пароль в `.env` можно оставить; `ADMIN_TOKEN_SECRET` можно
  сменить в любой момент (все войдут заново).
